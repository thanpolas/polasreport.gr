# /fuel roadmap - next feature wave

## Goal

Enhance the `/fuel` page so it becomes more analytically correct, easier to interpret, and more useful as a public reference tool, without compromising the current product principles:

- neutral copy
- no leading conclusions
- smallest possible UI surface
- progressive disclosure
- zero unnecessary dependencies
- visual consistency with the existing Polas Report style

---

## Scope summary

### In scope
1. EUR/USD normalization for Brent comparison
2. Lag analysis as an enhancement of the existing daily comparison chart
3. Harder and clearer methodology clarification
4. EU comparison layer
5. Multiple fuel support in the existing chart UI

### Out of scope for this phase
1. Taxes vs net price breakdown
2. Geography breakdown inside Greece
3. Large dashboard expansion
4. Any feature that significantly increases UI complexity without a strong analytical payoff

---

## Feature 1: EUR/USD normalization

### Problem
The current comparison is directionally useful but not fully fair, because Brent is quoted in USD per barrel while pump prices are shown in EUR per litre.

### Product objective
Allow the user to compare fuel prices against Brent in a way that better reflects the currency context of the Greek retail market.

### User value
- removes an obvious comparison objection
- improves credibility
- reduces "apples to oranges" criticism
- strengthens the page without changing its core UX

### Functional requirements
- fetch historical daily EUR/USD exchange rate data
- integrate it into the existing daily update job
- compute a Brent-in-EUR derived series for chart usage
- preserve the original Brent-in-USD series as a fallback or reference if needed
- support weekends and missing dates cleanly with deterministic carry-forward logic only where justified and documented

### Data pipeline requirements
- add a new script step to fetch or refresh historical FX data
- store output as a dedicated CSV, consistent with the current pipeline pattern
- merge FX data into the existing fuel + Brent normalization stage
- compute and expose:
  - brent_usd
  - eur_usd
  - brent_eur
- ensure date alignment is strict and explicit

### UX requirements
- default comparison should use FX-adjusted Brent
- keep the UI simple; do not expose technical controls unless necessary
- if a control is added, it should be a minimal segmented toggle:
  - FX adjusted
  - raw USD
- the default should favor clarity, not optionality

### Copy requirements
Use simple, neutral copy such as:

`Το Brent εμφανίζεται και προσαρμοσμένο σε ευρώ, ώστε η σύγκριση με την τιμή αντλίας να γίνεται στην ίδια νομισματική βάση.`

Avoid academic language and avoid sounding defensive.

### Acceptance criteria
- FX data updates automatically with the existing job
- chart can render Brent in EUR correctly across the full supported history
- no visible UX clutter is introduced
- methodology explains the adjustment in one clear sentence

## Feature 2: Lag analysis inside the existing daily comparison chart

### Problem
Users naturally expect pump prices to move on the same day as Brent. In reality, retail response often arrives with delay. Without this layer, the chart can look "wrong" even when it is mathematically correct.

### Product objective
Enhance the existing daily comparison chart so users can understand delayed response without introducing a separate analysis chart.

### Product direction
This is not a new chart.
This is an enhancement of the existing daily comparison chart.

### User value
- makes the relationship easier to see
- reduces confusion caused by same-day comparison
- gives the chart analytical depth without expanding the page

### Functional requirements
- support lag-adjusted comparison modes on the existing chart
- initial supported lags:
  - 0d
  - 3d
  - 5d
  - 7d
  - 10d
- compute lag by shifting Brent against fuel in time
- allow either:
  - manual lag selection
  - or auto-detected "best fit" with optional user override

### Recommended product behavior
Phase 1:
- keep manual lag selection simple
- default to `0d`
- allow the user to switch lag using a compact control

Phase 2:
- optionally compute best-fit lag and surface it as a hint, not as a loud claim

### UX requirements
- this must feel like a natural extension of the current chart
- no dropdowns
- no separate settings panel
- use a compact segmented button row or pill control
- the control must occupy minimal vertical space
- it should sit close to the chart header or in the same action bar as the series controls

### UI states
#### Default state
- chart shows same-day comparison
- lag control visible but quiet
- `0d` selected

#### Interactive state
- selecting a lag updates only the chart
- transition should feel immediate and lightweight
- no page reflow
- no modal
- no large explanatory block

#### Advanced hint state
- optional micro-copy under the chart:
  `Δοκιμάστε καθυστέρηση λίγων ημερών για να δείτε αν η αντλία ακολουθεί αργότερα το Brent.`

Keep this subtle and only if needed.

### Art direction
- the lag feature must look like a precision tool, not a toy
- controls should be visually secondary to the chart
- do not add color noise
- no badges, no flashy labels, no "AI-like" suggestions
- maintain the strict, disciplined style already established

### Copy requirements
If auto-fit is ever shown, use neutral wording such as:

`Η ισχυρότερη οπτική αντιστοίχιση στο τρέχον εύρος εμφανίζεται με καθυστέρηση 5 ημερών.`

Do not use causal or accusatory language.

### Acceptance criteria
- lag mode works inside the existing chart
- selected lag is obvious but visually discreet
- UX remains fast and uncluttered
- chart remains understandable with no additional charts added

## Feature 3: Hard methodology clarification

### Problem
The current methodology note is good, but still leaves room for lazy political readings and category errors.

### Product objective
Clarify the limits of the comparison in plain language, without weakening the usefulness of the page.

### User value
- improves trust
- prevents obvious misuse
- reduces predictable bad-faith objections

### Required methodology points
The methodology section should explicitly state, in plain language, that:

1. Brent is a benchmark for crude oil, not the final retail product sold at the pump
2. Pump prices do not react instantly
3. Brent futures and retail pump prices belong to different stages of the supply chain
4. The charts are comparative indicators, not proof of causation by themselves
5. FX-adjusted mode improves comparability but does not eliminate all structural differences

### UX requirements
- methodology must remain short
- the first layer should be readable in under 20 seconds
- deeper detail can be hidden behind progressive disclosure if needed
- do not turn the page into a white paper

### Copy direction
Tone:
- calm
- firm
- plain
- non-defensive

Suggested short copy:

`Το Brent είναι δείκτης τιμής αργού πετρελαίου, όχι η τελική τιμή του καυσίμου στην αντλία. Η αντλία επηρεάζεται με καθυστέρηση και από διαφορετικά στάδια της αλυσίδας αγοράς.`

Optional second sentence:

`Τα γραφήματα βοηθούν στη σύγκριση της πορείας των τιμών, όχι στην απόδοση αιτίας από μόνα τους.`

### Acceptance criteria
- methodology becomes harder to misread
- copy remains short and neutral
- page still feels like a public utility, not an argument

## Feature 4: EU comparison layer

### Problem
The current page is strong on Greece over time, but weaker on European context.

### Product objective
Add a comparison layer that shows how Greece sits relative to the EU average and a small set of relevant comparator countries.

### Comparison set
Recommended initial comparison group:
- EU average
- Italy
- Bulgaria
- Romania

### Why this set
- EU average gives the broad benchmark
- Italy gives a Mediterranean, southern-European benchmark
- Bulgaria gives a direct neighboring, Balkan benchmark
- Romania gives a second regional benchmark with a different market profile

This is enough context without turning the page into a cluttered European dashboard.

### Product direction
This should be implemented as a second comparison mode, not as an overloaded default chart.

### Functional requirements
- ingest weekly price data from the EU source
- support at minimum:
  - unleaded 95
  - diesel
- normalize dates cleanly against the site’s existing data model
- allow a comparison view between:
  - Greece
  - EU average
  - selected comparator countries

### UX requirements
- do not show all EU countries by default
- do not use a giant multi-select list
- default comparison set should be curated
- use compact country pills or segmented buttons
- allow up to 3 external series visible at once to avoid visual overload
- Greece should remain pinned and always visible

### Recommended default
- Greece
- EU average
- Italy
- Bulgaria

Romania can be available as an additional optional comparator.

### Art direction
- comparison controls must be visually restrained
- charts must remain readable at first glance
- emphasize Greece as the anchor series
- all comparison series should be clearly secondary in hierarchy

### Copy requirements
Use simple framing such as:

`Σύγκριση με μέσο όρο ΕΕ και επιλεγμένες χώρες αναφοράς.`

Avoid patriotic or rhetorical framing.

### Acceptance criteria
- EU comparison adds context without turning the page into a dashboard
- visible series count remains manageable
- Greece stays the primary reference
- users can compare against a small, meaningful benchmark set

## Feature 5: Multiple fuels in the existing chart system

### Problem
The page already has multiple fuel types in the data, but the chart experience still revolves mainly around unleaded 95.

### Product objective
Allow the same chart system to switch fuel type with minimal UI cost and no conceptual clutter.

### Supported fuels
Initial target:
- Unleaded 95
- Diesel
- Unleaded 100
- Autogas

### Product direction
Do not duplicate charts per fuel.
Do not stack multiple fuels together by default.
Use one chart framework with lightweight fuel switching.

### UX requirements
- fuel switching must be compact, obvious, and low-noise
- control must take minimal space
- should behave like a small segmented control or pill row
- must work well on both desktop and mobile
- avoid wrapping into ugly multi-line layouts where possible

### Recommended control behavior
#### Desktop
- compact horizontal segmented control above chart
- short labels:
  - 95
  - Diesel
  - 100
  - LPG

#### Mobile
- horizontally scrollable pill row if needed
- maintain tap targets without increasing vertical height too much

### UI states
#### Default state
- `95` selected
- selection is visually clear
- control is visible but not dominant

#### Hover / focus state
- subtle emphasis only
- no animation gimmicks

#### Active state
- selected fuel becomes the primary series immediately
- chart title / metric cards update consistently where relevant
- no full redraw flash or layout shift

#### Disabled / unavailable state
- if a fuel lacks enough history or data quality, it should be disabled gracefully
- avoid showing broken states or empty charts

### Data requirements
- all existing fuel series should flow through the same chart data contract
- chart logic must not fork unnecessarily per fuel type
- cumulative and daily views should update from the active fuel selection

### Copy requirements
Keep labels short and purely functional.
No explanatory paragraph is needed if the control is self-evident.

### Acceptance criteria
- users can switch fuels with one tap
- no extra chart copies are introduced
- UI stays compact
- all major chart modes work with the selected fuel

## Technical notes

### Architecture principles
- preserve the existing zero-dependency philosophy where possible
- extend the current Node.js ESM pipeline rather than introducing new infrastructure
- prefer precomputed JSON over runtime-heavy transforms
- keep the frontend conditional and page-scoped as it is now

### Data model expectations
The merged chart payload should evolve to support:
- raw Brent series
- FX-adjusted Brent series
- lag-adjusted comparative series
- multiple fuels
- optional EU comparison series

### Frontend principles
- one chart system, multiple lenses
- no dashboard sprawl
- no visual over-explanation
- keep controls compact and local to the chart they affect

---

## Non-goals

The following are explicitly not part of this phase:
- tax decomposition
- ex-tax vs retail decomposition
- regional Greece breakdown
- full-EU explorer mode
- explanatory editorial content inside the page
- turning the page into a conclusion engine

---

## Definition of success

This phase succeeds if:

1. the comparison becomes harder to dismiss on technical grounds
2. the page remains simple enough to understand at a glance
3. users gain more analytical depth without paying a UI complexity cost
4. the page becomes more credible as a reusable public reference tool
