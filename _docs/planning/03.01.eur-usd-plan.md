# Plan: EUR/USD Normalization for Brent Comparison

## Context

The /fuel page compares Greek pump prices (EUR/litre) against Brent crude (USD/barrel). This is an apples-to-oranges comparison because currency fluctuations distort the relationship. Adding EUR/USD exchange rate data allows computing Brent in EUR, making the comparison fair and credible.

## Data Source Selection

### Primary: FRED DEXUSEU (same provider already used for Brent)
- URL: `https://fred.stlouisfed.org/graph/fredgraph.csv?id=DEXUSEU&cosd={start}&coed={end}`
- Format: CSV `observation_date,DEXUSEU` (USD per 1 EUR)
- Coverage: 1999-01-04 to present, daily (weekdays)
- Lag: ~1 week (same as Brent FRED)
- Handles both historical bulk AND daily incremental -- same script, same pattern

### Fallback: Frankfurter API (wraps ECB data, fills FRED's lag gap)
- URL: `https://api.frankfurter.dev/v1/{start}..{end}?base=EUR&symbols=USD`
- Format: JSON `{ rates: { "2026-03-01": { USD: 1.1585 } } }`
- Near-realtime updates (~16:00 CET), no API key, no rate limits
- Unlike Yahoo (Brent fallback, ~45 days only), Frankfurter supports full historical ranges

### Conversion: `brent_eur = brent_usd / eur_usd_rate`

## Design Decisions

1. **Separate script** (`fetch_eurusd_prices.mjs`) -- mirrors `fetch_brent_prices.mjs` pattern; one concern per script
2. **Separate CSV** (`eurusd_prices.csv`) -- Brent and FX have different holiday calendars; separate files avoid null-column mess
3. **Persist brent_eur conversions in a CSV** -- `generate_fuel_json.mjs` writes `_fuel-pdfs/brent_eur_prices.csv` (date,brent_usd,eur_usd,brent_eur) incrementally. On subsequent runs, only new/updated dates are recomputed and appended. This avoids recalculating the full history on every pipeline run. The JSON generator reads from this pre-computed CSV instead of re-deriving brent_eur across 800+ rows each time
4. **EUR/USD is optional** -- if CSV missing, pipeline proceeds with null values; no breakage
5. **No schema versioning needed** -- JSON additions are purely additive; frontend ignores unknown keys

## Implementation

### Step 1: New file `_scripts/fetch_eurusd_prices.mjs`

Clone pattern from `fetch_brent_prices.mjs`:
- CSV: `_fuel-pdfs/eurusd_prices.csv` with header `date,rate,source`
- `fetchFromFRED(start, end)` -- same CSV parsing, skip `.` values
- `fetchFromFrankfurter(start, end)` -- parse JSON `rates` object, return `{date, rate, source: "frankfurter"}`
- Main: load Map, find last FRED date, fetch FRED (overwrites), fetch Frankfurter (gap-fill), write sorted CSV
- First run starts from 2023-01-01 (matching fuel data); subsequent runs are incremental

### Step 2: Modify `_scripts/generate_fuel_json.mjs`

- Add `EURUSD_CSV` and `BRENT_EUR_CSV` paths
- Parse `eurusd_prices.csv` into `eurUsdByDate` Map (optional -- warn if missing)
- **Incremental brent_eur computation**: load existing `brent_eur_prices.csv` into a Map. Only compute `brent_eur` for dates not already in the CSV (new dates since last run). Append new rows and write back. This means daily runs only compute 1-2 new conversions, not the full 800+ row history
- `brent_eur_prices.csv` schema: `date,brent_usd,eur_usd,brent_eur` -- persists all three values so conversions are auditable and reproducible
- For the JSON output, read from the persisted `brent_eur_prices.csv` rather than re-deriving
- Add computed series: `pct_brent_eur` (daily % change of brent_eur)
- Add to `latest`: `eur_usd`, `brent_eur`
- Add to `latest.avg_365`: `eur_usd`, `brent_eur`
- Add to `series`: `eur_usd`, `brent_eur`, `pct_brent_eur`
- Copy `eurusd_prices.csv` and `brent_eur_prices.csv` to `assets/data/`

### Step 3: Update `package.json`

Add `"fuel:eurusd": "node _scripts/fetch_eurusd_prices.mjs"` and insert into `fuel:daily` and `fuel:update` chains (after `fuel:brent`, before `fuel:json`).

### Step 4: Update `.github/workflows/fuel-daily-update.yml`

Add step "Fetch EUR/USD exchange rates" between Brent and JSON generation. Add `eurusd_prices.csv` to S3 upload.

### Step 5: Update `fuel/index.html`

Add EUR/USD CSV download link in Open Data section. Add FRED DEXUSEU attribution to methodology.

### Frontend changes (NOT in this task)

The data contract delivers `brent_eur`, `pct_brent_eur`, `eur_usd` in the JSON. Frontend work to switch charts to EUR-adjusted mode is a separate task.
